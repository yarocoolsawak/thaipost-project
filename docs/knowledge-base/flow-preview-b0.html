หนึ่ง shipment มีหนึ่งเคสตลอดอายุ: เคยแจ้งแล้วไม่เปิดใหม่ทั้งร้านค้าและงาน SLA แม้เคสปิดแล้ว · แสดง “เคยแจ้งแล้ว / ผลที่จบแล้ว / สถานะพัสดุล่าสุดและเวลาอัปเดต” · ร้านค้าพิมพ์ต่อได้ สาขาได้รับแจ้งข้อความใหม่ เคสกลับเป็นรอสาขาตอบ เก็บประวัติปิดเดิมไว้

ตัวตน 2 ชั้น: shipment_id ระบุการจัดสรรเลขให้กล่อง ผูก merchant_id + order_id + shipment_sequence · parcel_id ระบุรอบรับฝากของ ปณท ที่ยืนยันแล้ว · เลขเดียวกันถูก reuse หลัง 6 เดือนได้ แต่เป็น shipment_id และ parcel_id ใหม่ · ไม่ใช้เลขพัสดุหรือ order_id อย่างเดียวเป็น key

จับคู่ข้อมูลก่อนแสดง: ใช้ allocation / shipment ref หรือ cycle id จาก ปณท ถ้ามี; ถ้าไม่มี ใช้หลักฐานจัดสรรเลขและรับฝากที่จับคู่ได้แน่นอน เวลาและ postcode เป็นข้อมูลประกอบ · หลายรอบหรือยังยืนยันไม่ได้ให้พักข้อมูลให้ CS ตรวจ ห้ามเลือกรอบแรกหรือเดาว่าครบ 6 เดือนแล้วเป็นรอบใหม่ · ภาพก็ต้องยืนยันรอบก่อนแสดง

Webhook: แยกเวลาเกิดเหตุการณ์จากเวลารับข้อมูล กัน event ซ้ำ เก็บ event ที่กำกวมรอตรวจ ไม่ทับสถานะปัจจุบันด้วย event เก่า และไม่ย้ายเคส/แชทข้าม shipment · เปิดเคสเดิมได้แม้ API ล่ม แสดงข้อมูลล่าสุดที่เก็บไว้พร้อมเวลา

สาขาเห็นทุกเคส: เมื่อระบุสาขาแล้วให้สาขาและ CEC เห็นทันที รวมเคสที่ระบบหรือ CS ตอบเอง; การเห็นเคสแยกจากการต้องลงมือตอบ · หน้า “คำสั่งซื้อสำเร็จ” ไม่มีปุ่มแจ้งเคส · งาน SLA ไม่เปิดเคสให้ shipment ที่จบแล้ว (ส่งสำเร็จ / คืนต้นทางเสร็จ / ยกเลิก)

กติกาปิดเคส · ยืนยัน 2 พ.ย. 2569

กรณีเริ่มนับ / การดำเนินการผลและเหตุผลใน log
ระบบเปิดติดตาม SLA เอง ยังไม่มีเรื่องจากร้านค้าสถานะนำจ่ายสำเร็จที่ยืนยันตรง shipment/รอบ · เคสยังเปิด · ไม่ใช่ข้อยกเว้นปิดอัตโนมัติ → Archived · “ปิดอัตโนมัติ เนื่องจากสถานะพัสดุนำจ่ายสำเร็จแล้ว”
เคสทั่วไป ส่งผลแก้ไขแล้วรอร้านค้ายืนยัน 72 ชั่วโมง (3 วัน default ปรับแยกประเภทได้) นับจากส่งผลแก้ไขถึงร้านค้าสำเร็จ · เตือนเมื่อเหลือ 24 ชั่วโมงกดยอมรับ = ปิดทันที · ไม่ตอบจนครบ = ปิดอัตโนมัติ → Archived · “ปิดอัตโนมัติ เนื่องจากไม่มีการตอบกลับภายใน 3 วัน” ไม่บันทึกว่าร้านค้ายอมรับ/ได้รับของ
เซ็นรับแล้วไม่ได้รับของยกเว้นการปิดอัตโนมัติทุกทาง ทั้งนำจ่ายสำเร็จและหมดเวลาตอบ · ครบ 3 วันเตือน CS/สาขาให้ติดตามปิดได้เมื่อร้านค้ากดยอมรับและปิดเคสเท่านั้น สาขาตอบ/แนบภาพ/CS ตรวจแล้ว หรือร้านค้าเงียบ ไม่ทำให้ปิด
ร้านค้ากด “ยังไม่จบ” หรือส่งข้อความ/รูปยกเลิกเวลาปิดทันที กลับ waiting_handler แจ้งสาขา · ถ้าปิดแล้วเปิดดำเนินการต่อใน case_id เดิมเก็บประวัติปิดเดิม · ไม่ให้ webhook นำจ่ายสำเร็จปิดซ้ำ · ข้อยกเว้นยังคงอยู่จนร้านค้ายอมรับ

ตัวจับเวลาผูกกับรุ่นผลแก้ไข: ส่งผลแก้ไขรอบใหม่จึงเริ่มนับรอบใหม่ ข้อความภายใน/สถานะพัสดุ/ส่งซ้ำไม่รีเซ็ตเวลา · job ตรวจ state รุ่นคำตอบ กำหนดเวลา และข้อยกเว้นอีกครั้งใน transaction ก่อนปิด · Archived เป็นที่แสดงเคสปิด ไม่ใช่ผลยืนยันรับของ

ข้อยกเว้นบันทึกเป็น delivery_disputed และ merchant-only แยกจากประเภทที่แสดง ไม่ให้แก้ประเภทเพื่อหลบกฎ · log เก็บผู้ทำ เวลา เหตุผล สถานะก่อน–หลัง และ event/รุ่นคำตอบที่อ้างอิง · กรณี “เซ็นรับแล้วไม่ได้รับของ” เข้าได้จากแจ้งเตือน/รายละเอียดติดตามพัสดุ หากมีเคสแล้วใช้เคสเดิม ไม่เพิ่มปุ่มแจ้งใหม่ในหน้ารายการคำสั่งซื้อสำเร็จ
